# r21 fail-fast successor plan

## Decision

While the immutable r20 live screening cohort was running, its first three
terminal units already contained transport-failure rates incompatible with the
pre-registered 2% unit gate. The r20 run remains active and is not interrupted:
its complete denominator and terminal evidence are required for the audit.

An offline successor plan was therefore prepared so that the next cohort can
start without another planning delay if r20 conversion is blocked.

- Tasks: 22

- Concurrency: serial (`max_workers=1`)
- Fail-fast policy: enabled only after the transport-failure rate is
  mathematically unable to pass; cancelled cases remain denominator failures.

## Safety boundary

The r21 plan uses the same non-target source and live-probe bindings as the
current screening boundary, but it is a distinct pre-registered cohort. It has
not started a provider request, does not replace r20, and cannot be used to
backfill or erase r20 failures. Ranking conversion and the baseline freeze
remain closed until r20 is terminal.

## Verification

The plan was generated by `baseline-screening-plan` with the fail-fast option,
and its offline receipt reported `ready=true` with no blockers. The repository
working tree remained clean after the receipt and documentation update.
